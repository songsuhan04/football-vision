# football-vision

축구 영상에서 선수 움직임을 **2D 격자 히트맵 · 이동 궤적**으로 시각화하고,
**AI가 선수별 움직임과 팀 전술을 자연어로 분석**하는 전력분석 도구.

> 상태: **계획 수립 완료, 구현 전.** 전체 설계는 [`docs/PLAN.md`](docs/PLAN.md) 참고.

---

## 무엇을 하는가

```
경기 영상 → 선수 탐지 → 경기장 키포인트 → 호모그래피(화면→경기장 좌표)
         → 추적 → 2D 좌표 시계열 → 히트맵 · 궤적 · 속도 · 팀 형태 지표 → AI 리포트
```

- **2D 격자 히트맵** — 경기장을 바둑판(12×8)으로 나눈 선수별/팀별 체류 분포
- **이동 궤적** — 짧은 구간에서는 히트맵보다 궤적선이 훨씬 잘 읽힌다
- **동기화 재생** — 원본 영상과 2D 탑다운 레이더를 같은 타임라인으로 나란히
- **AI 전술 리포트** — 집계 지표를 Claude API에 넘겨 선수 움직임·팀 전술 분석

## 아키텍처

무거운 CV 연산은 **Google Colab (T4 GPU)**, 시각화는 **로컬 Next.js**.
둘은 실시간 API가 아니라 **`analysis-bundle.json` 파일 하나**로 연결된다.

```
[Colab · T4 GPU]                              [로컬 · npm run dev]
영상 → CV 파이프라인 → analysis-bundle.json  ──▶  드래그앤드롭 → 대시보드
```

Colab은 서버가 아니라(세션 종료·고정 URL 없음) 실시간 호출 구조를 쓰지 않는다.
이 파일 기반 설계는 나중에 클라우드 GPU로 자동화할 때 **웹 코드를 그대로 재사용**하는 마이그레이션 경로가 된다.

## 2-Stage 전략

| 단계 | 영상 | 목적 |
|---|---|---|
| **Stage 1** | 해외 프로 중계 | Roboflow 모델의 **학습 도메인** → 정확도가 보장되는 조건에서 파이프라인 + 웹 완성 |
| **Stage 2** | 직접 촬영한 아마추어 리그 | 실제 전력분석 대상 |

아마추어 영상으로 바로 시작하면 문제가 터졌을 때 *"코드가 틀렸나, 영상이 어려운가"* 를 구분할 수 없다.
모델이 잘 되는 조건에서 먼저 완성하면 Stage 2에서 **남는 문제가 CV 정확도 하나로 좁혀진다.**

전환 비용은 웹 0, 파이프라인 구조 0 — 실질 비용의 90%는 모델 정확도 확보다.
그래서 임계값을 하드코딩하지 않고 `notebook/pipeline/presets.py` 에 `broadcast` / `handheld_elevated` 프리셋으로 묶는다.

## 구조

```
notebook/          Colab 노트북 + 파이프라인 모듈 (얇은 노트북, 로직은 pipeline/)
  pipeline/        presets · windows · detect · pitch · teams · metrics · export ...
web/               Next.js 15 — 히트맵 · 궤적 · 동기화 재생 · 라벨링 · AI 리포트
docs/PLAN.md       전체 설계 문서
```

## 주의

- **영상 파일은 커밋하지 않는다** (`.gitignore` 의 `web/public/videos/`, `*.mp4`).
  저작권 안전선이자 리포 용량 방어선이다.
- 중계 영상은 **내부 분석 용도로만** 사용하며 재배포하지 않는다.
- API 키는 `.env.local` 에만 둔다 (`.env*` 는 gitignore 대상).
